# Design Write-Up

## Architecture

Single TypeScript process, files on disk, one CLI — deliberately, per the brief's anti-scaling note. The design effort went into **boundaries**, which are enforced as an import graph, not a convention:

- **`Surface`** (`src/surface/surface.ts`) is the perception/action seam: `observe() → Observation`, `act(SemanticAction)`, `resolve(TargetRef)`. Driver code lives below the seam: only the web surface (`src/surface/web/`) and the HITL layer (which hands the live page to a human and watches what they do) touch Playwright; the agent, replay engine, compiler, and policy layers speak exclusively in observations, semantic actions (`activate`, `setValue`, `read`…), and semantic target descriptors. An `Observation` is a frame-aware element map (roles, accessible names, row/column anchors, geometry) computed by an in-page walker plus a screenshot. For ARIA-free legacy markup this is precisely what the browser's accessibility tree would contain; computing it in one pass adds the anchors and geometry we need without brittle AX-node→DOM joins across framesets.
- **`ActionGate`** (`src/policy/actionGate.ts`) is the single choke point: *every* action — LLM discovery and deterministic replay alike — is authorized here (origin/path allowlist, action-kind allowlist, risk class, HITL control token). Nothing else calls `surface.act()`. The model has no privileged path to the UI.
- **Discovery and replay never import each other.** The capability artifact is their only interface — the brief's through-line expressed as a dependency rule. The compiler (`discovery/compile.ts`) is deterministic code: it prunes probe/retracted actions, parameterizes strictly by value-matching against declared params, canonicalizes origins to `{baseUrl}`, and mines checkpoints from observed state deltas. The LLM contributes intents and descriptions (prose); nothing executable comes from the model.

Key trade-off: the target app is a **local mock** ("MockCore Teller") built legacy-hostile on purpose — framesets, table layout, no test IDs — with deterministic fault injection. Versus a public demo site this costs realism points but buys reproducible error evidence, zero ToS/PII risk, and lets evaluators re-run every scenario offline. The interesting problems (frames, table anchoring, runtime errors, supervisor gates) are all present.

## Artifact schema

The artifact (`src/schema/capability.ts`, Zod) is a **contract an agent can call**, not a step list. Shape and reasoning:

- **Typed params** with `sensitivity` (`none|internal|pii|secret`) and `source` (`caller|env`). The schema *rejects* caller-supplied secrets: credentials resolve from the environment at invocation time, so no secret can ever be serialized into an artifact. Typed **outputs** point at the read step that produces them. **Outcomes, recoveries, and anomalies are first-class top-level sections** — "no such member" is representable only as an outcome, so conflating it with a failure is structurally impossible.
- **Steps** carry a human `intent` line (the review surface), a semantic action, `{param}` bindings, pre/postconditions, a wait policy, and a risk class. The schema rejects state-transition steps (navigate/activate) without a postcondition checkpoint.
- **Targets are ordered locator ladders** — `roleName` → `labelText` → `textAnchor` (self/rowOf) → `tableCell` (row anchor × column header) → an explicitly surface-tagged `structural` CSS last resort. The recorded `snapshot` (anchor-scrubbed text context, geometry, screenshot ref) exists for review and drift evidence and is never used for resolution.
- **Versioned + reviewable**: semver with stated semantics (patch = locator/wait tuning; minor = new optional param/outcome/recovery; major = contract change), provenance tying the artifact to its discovery run's evidence, an `approval: draft|approved` state (drafts refuse unattended replay — the shipped artifact was reviewed and approved by name), and a canonical-JSON sha256 so silent edits are detectable.
- One condition vocabulary (`textPresent`, `elementPresent`, `urlMatches`, `dialogOpen`, `all/any`) serves checkpoints, outcome detectors, recovery triggers, anomaly screens, and success criteria — one evaluator function, so the engine's classification order is meaningful.

Discovery-time grounding matters: `declare_outcome` is only accepted if its text marker is literally visible on screen, and the agent probes exceptional states (the 99999 search) in an explicitly marked probe segment that is excluded from the replayable spine. Detectors are evidence, never invention.

## Determinism & error handling

Replay (`src/replay/engine.ts`) interprets the artifact with no model. Determinism comes from three mechanisms: the **locator ladder** (first strategy yielding exactly one confident candidate wins; two near-equal candidates are a hard `TARGET_AMBIGUOUS` refusal — a deterministic engine must never guess in a banking app), **condition-based waiting** (postconditions are polled; there are no fixed sleeps), and **explicit state classification**. Every observation during a step's wait is classified in strict priority:

**postcondition satisfied → expected business outcome → known recovery (bounded per-recovery attempts + a global budget) → declared anomaly / unknown dialog → timeout.**

The ordering is a design claim: outcomes outrank recoveries, so a "not found" page that is also slow reports the business outcome rather than being retried into confusion. Outcome detectors are deliberately step-scoped (`onDetect`) while recoveries/anomalies are global — global text detection risks false positives on legacy screens, so an outcome surfacing off-script reports as a timeout with full state rather than a guessed classification; region-scoped conditions are the designed fix (see Cuts). The result contract is four-way — `success` (typed outputs) / `business_outcome` (named code) / `escalated` / `failed` (class, stepId, expected, observed, screenshot) — and failures name nine classes (`INVALID_PARAMS`, `TARGET_NOT_FOUND`, `TARGET_AMBIGUOUS`, `PRECONDITION_FAILED`, `POSTCONDITION_TIMEOUT`, `UNEXPECTED_STATE`, `RECOVERY_EXHAUSTED`, `POLICY_BLOCKED`, `SURFACE_ERROR`). Every result — failures and escalations included, which is exactly when a caller needs forensics — carries the step traces, recoveries used, interventions, and an `irreversibleCompleted` flag: the signal a calling agent needs to decide whether a failed run is safe to retry. Recovery handlers are deliberately few: dismiss a known interstitial, answer a known dialog, restart the run (refused once any irreversible step completed), escalate to a human. Native dialogs are *held* and surfaced as observed state — auto-accepting a `confirm()` is exactly the wrong default here.

UI drift (secondary, per the brief): every resolution logs which ladder strategy fired; a step that used to resolve at strategy 0 and now needs strategy 2 is a drift signal captured on every replay for free, and the failure path degrades gracefully through the ladder before refusing.

## Heterogeneity & multi-tenant

**Surface abstraction:** the artifact never contains driver concepts — semantic actions and semantic locators only. A desktop surface (UIA/MSAA on Windows, AX on macOS) implements the same `Surface` interface: `activate` becomes `Invoke()`, `roleName/labelText/tableCell` map onto the same accessibility semantics those APIs expose, `urlMatches` maps to window/pane identity, and the one web-only strategy (`structural`) is surface-tagged so other drivers skip it instead of misinterpreting it. Legacy web needs no new schema at all — the mock *is* legacy web (framesets, table soup), and frames are addressed by name/URL pattern, never index. The seam is proven in practice: the discovery agent, replay engine, and policy gate share one Surface implementation without importing the driver.

**Multi-tenant reuse:** artifacts identify the **vendor product** (`app: mockcore-teller`), not the tenant. Tenants bind via **overlays** (`src/schema/overlay.ts`): required `baseUrl` binding plus patches that are *additive and narrow by construction* — `prependStrategy` (tenant re-skinned a control), `addRecovery` (tenant-specific interstitial), `overrideWait` (slower instance). The schema gives overlays no way to change actions, params, outputs, or risk, so a tenant override can never silently change what a capability does. This is implemented and exercised live: the compiled artifact ships with only the handling its discovery run observed, and the `demo-fcu` overlay adds the session-timeout recovery — the evidence's timeout replay runs through it. Drift management: per-step strategy-rank telemetry across a tenant fleet is the signal (strategy-rank regressions cluster by tenant → their skin changed → patch the overlay or re-review); version pinning via the overlay's `^1` range plus artifact semver keeps specialization safe.

## Escalation & handoff

**Detecting "stuck"** is explicit, not heuristic: (1) an irreversible action under policy mode `escalate` pauses *before* acting; (2) an `escalate`-type recovery matches a state only a human can clear (supervisor authorization); (3) with no operator attached, either case ends the run as `escalated / no_operator_available` — the system never guesses past a human decision.

**Control transfer is mechanical.** The `SessionController` owns a control token; the ActionGate checks `holder()` on *every* action, so while a handoff is open the automation physically cannot act — possession is enforced at the same choke point as the allowlist. Nothing is "transferred" except control: the human operates the literal same browser context (same cookies, same server session), which is why state survives the handoff by construction. The **intervention request** carries capability/step/intent, the reason, a live-state summary, a screenshot, the suggested resolution, and the legal options; it is written to evidence and rendered to the operator.

**Handing back:** the operator resolves `approve` (the agent performs the pending risky action exactly once, with approval attached), `resume` (the human did the work), or `abort`. Resume verification reuses the engine's own machinery — after a handoff the engine re-enters its classification loop, so **the step's postcondition judges the human's work** with the same vocabulary that judges the machine's. Human actions during the handoff are captured (click/change/submit with a structural target description, values recorded as length only) and appear in the run log between `intervention_raised` and `intervention_resolved` — with provably zero gate-approved agent actions in between. The operator surface is a terminal prompt plus the live headed window (mocked thin, as the brief allows); a remote console would implement the same `Operator` interface over CDP screencast without touching the controller — that seam is the design.

## Safety

The model: **one gate, allowlist-first, risk-tiered, redact-at-the-boundary.** The configurable policy allowlists origins, path prefixes (the mock's `/__faults` test harness is denied to the agent), and action kinds — checked against both the top-level page and the target element's own frame, since a page on an allowed origin can embed an off-origin frame. Risk classes: `read` and `reversible` proceed; `irreversible` is handled per policy — `block`, `confirm`, or `escalate` (default). I chose *escalate* as the default because in back-office banking the right reviewer for a one-off irreversible action is a person with context, on the live session — and the evidence shows that path working. Under the default policy, unattended replay of an irreversible flow is structurally impossible.

Data handling: sensitivity annotations drive redaction applied at the **write boundary** (one auditable place), so secrets never reach disk in artifacts, logs, transcripts, or results (`«secret:operatorPassword»`), and `pii` values are masked in evidence while the caller still receives real outputs on its channel. The discovery agent references secret params **by name** — the harness injects values, the model never sees them, and password field values are never observed at all. Sensitive extractions get the same treatment at the moment they exist: a `pii`-classed read is registered with the redactor immediately and shown to the model only in masked form, so the model cannot echo it into artifact prose — and the shipped artifact file itself passes through the redactor. The compiler additionally scrubs recorded neighbor text (names, dates, balances) from artifact snapshots, keeping only anchor tokens. Limits, honestly: screenshots are not redacted (a real deployment needs region masking driven by the same sensitivity annotations); redaction is exact-string substitution over *classified* values — incidental on-screen data that is never declared as a param or output still appears in transcripts and screenshots, which a real deployment would address with app-profile field classification; and the allowlist constrains *where* the agent acts, not *what* it reads within allowed pages — extraction is at least auditable because `read` is a gated action.

## Cuts

Deliberate, each with a designed seam: **(1) Operator console UI** — terminal + live window only; next: a CDP-screencast web console implementing the same `Operator` interface. **(2) Desktop surface** — design only, per the brief; next: `surface/desktop/` behind the same `Surface` interface with the locator-strategy mapping above. **(3) Second tenant variant app** — the overlay *mechanism* is implemented, unit-tested, and exercised live, but no re-skinned second instance was built; next: a branded MockCore variant proving `prependStrategy` against a real rename. **(4) Discovery of the risky flow** — `openSubAccount` is hand-authored because discovery-time irreversible actions need the HITL approval path wired into the agent loop (the gate already blocks them); next: pass the controller into discovery so a human approves risky clicks during recording. **(5) Assisted LLM fallback on replay failure** — designed (one bounded, policy-checked step that *proposes an artifact patch* rather than silently healing) but not built, keeping the production path provably LLM-free. **(6) Multi-run stability scoring & approval workflow** — the `approval` state and drift telemetry exist; the workflow around them doesn't. **(7) Keystroke-perfect human capture and screenshot redaction** — event-level capture and text-only redaction shipped; limits documented above. **(8) Region-scoped conditions and mid-flow resume** — `textPresent` is page-global (scoped checks exist via `elementPresent`), and `restartRun` is the only session-recovery primitive; region-scoped text conditions and resume-from-step (with a re-auth subflow) are the designed next iterations of the condition vocabulary and recovery handlers.
