# Design Write-Up

## Architecture

Single TypeScript process, files on disk, one CLI — deliberately, per the brief's anti-scaling note. The design effort went into **boundaries**, which are enforced as an import graph, not a convention:

- **`Surface`** (`src/surface/surface.ts`) is the perception/action seam. Only the web surface (`src/surface/web/`) and the HITL layer (which hands the live page to a human) touch Playwright; the agent, replay engine, compiler, and policy layers speak exclusively in observations, semantic actions (`activate`, `setValue`, `read`…), and semantic target descriptors. An `Observation` is a frame-aware element map — roles, accessible names, row/column anchors, geometry, computed by an in-page walker — plus a screenshot.
- **`ActionGate`** (`src/policy/actionGate.ts`) is the single choke point: *every* action — LLM discovery and deterministic replay alike — is authorized here (origin/path allowlist, action-kind allowlist, risk class, HITL control token). Nothing else calls `surface.act()`. The model has no privileged path to the UI.
- **Discovery and replay never import each other**; the capability artifact is their only interface. The compiler (`discovery/compile.ts`) is deterministic code: it prunes probe/retracted actions, parameterizes strictly by value-matching against declared params, canonicalizes origins to `{baseUrl}`, and mines checkpoints from observed state deltas. The LLM contributes intents and descriptions (prose); nothing executable comes from the model.

Key trade-off: the target app is a **local mock** ("MockCore Teller") built legacy-hostile on purpose — framesets, table layout, no test IDs — with deterministic fault injection. Versus a public demo site this costs realism points but buys reproducible error evidence, zero ToS/PII risk, and offline re-runs of every scenario; the interesting problems (frames, table anchoring, runtime errors, supervisor gates) are all present. Concretely: the shipped artifact came from a single 15-turn `claude-opus-4-8` discovery run (~130k input tokens, ≈ $2 at Opus pricing — `evidence/discovery/20260815-225407-02b9/`) that compiles to a 9-step artifact and replays deterministically in under 3 seconds.

## Artifact schema

The artifact (`src/schema/capability.ts`, Zod) is a **contract an agent can call**, not a step list. Shape and reasoning:

- **Typed params** with `sensitivity` (`none|internal|pii|secret`) and `source` (`caller|env`). The schema *rejects* caller-supplied secrets: credentials resolve from the environment at invocation time, so no secret can ever be serialized into an artifact. Typed **outputs** point at the read step that produces them. **Outcomes, recoveries, and anomalies are first-class top-level sections** — "no such member" is representable only as an outcome, so it simply can't be filed as a failure.
- **Steps** carry a human `intent` line (the review surface), a semantic action, `{param}` bindings, pre/postconditions, a wait policy, and a risk class. The schema rejects state-transition steps without a postcondition checkpoint.
- **Targets are ordered locator ladders** — `roleName` → `labelText` → `textAnchor` → `tableCell` (row anchor × column header) → a surface-tagged `structural` CSS last resort. The recorded `snapshot` (anchor-scrubbed text context, geometry, screenshot ref) is review/drift evidence, never used for resolution.
- **Versioned + reviewable**: semver with stated semantics (patch = locator/wait tuning; minor = new optional param/outcome/recovery; major = contract change), provenance tying the artifact to its discovery run's evidence, an `approval: draft|approved` state (drafts refuse unattended replay; the shipped artifact was reviewed and approved by name), and a canonical-JSON sha256 so silent edits are detectable.
- One condition vocabulary (`textPresent`, `elementPresent`, `urlMatches`, `dialogOpen`, `all/any`) serves checkpoints, outcome detectors, recovery triggers, anomaly screens, and success criteria — one evaluator function, so the classification order is meaningful.

Discovery-time grounding: `declare_outcome` is accepted only if its text marker is literally visible on screen, and exceptional-state probes (the 99999 search) run in a marked segment excluded from the replayable spine. Detectors only encode text the run actually saw.

## Determinism & error handling

Replay (`src/replay/engine.ts`) interprets the artifact with no model. Determinism comes from three mechanisms: the **locator ladder** (first strategy yielding exactly one confident candidate wins; near-equal candidates are a hard `TARGET_AMBIGUOUS` refusal — the engine never guesses), **condition-based waiting** (postconditions are polled; no fixed sleeps), and **explicit state classification**, in strict priority:

**postcondition satisfied → expected business outcome → known recovery (bounded per-recovery attempts + a global budget) → declared anomaly / unknown dialog → timeout.**

The ordering is a design claim: outcomes outrank recoveries, so a "not found" page that is also slow reports the business outcome rather than being hammered by retries.

The result contract is four-way — `success` (typed outputs) / `business_outcome` (named code) / `escalated` / `failed` — where `failed` carries one of nine named classes plus what step, what was expected, and what was observed (`src/schema/result.ts`). Every result, including failures and escalations, carries the step traces, recoveries used, interventions, and an `irreversibleCompleted` flag — the signal a calling agent needs to decide whether a failed run is safe to retry. Outcome detectors are step-scoped (`onDetect`), and text conditions can additionally be **frame-scoped** (`textPresent` with a frame hint), so persistent chrome — a nav menu, a banner — can never satisfy a checkpoint about the work area. The compiler exploits both: mined checkpoints are scoped to the frame the action happened in and ranked by specificity (longest new marker first), and the compiler *lints its own weak choices* into `compile-report.json` ("checkpoint may be non-specific") so a reviewer sees them at approval time. It also parameterizes outcome markers that echo the probe entity — else the detector stays pinned to the recorded entity — flagged in the report because templating a detector deserves explicit review. Recovery handlers are few: dismiss a known interstitial, answer a known dialog, restart the run (refused once any irreversible step completed), escalate to a human. Native dialogs are *held* and surfaced as observed state — auto-accepting a `confirm()` is the wrong default in banking.

UI drift (secondary, per the brief): every resolution logs which ladder strategy fired — a step that used to resolve at strategy 0 and now needs strategy 2 is a drift signal captured on every replay for free.

## Heterogeneity & multi-tenant

**Surface abstraction:** the artifact never contains driver concepts — semantic actions and semantic locators only. A desktop surface (UIA/MSAA on Windows, AX on macOS) implements the same `Surface` interface: `activate` becomes `Invoke()`, `roleName/labelText/tableCell` map onto the accessibility semantics those APIs expose, `urlMatches` maps to window identity, and the one web-only strategy (`structural`) is surface-tagged so other drivers skip it. Legacy web needs no new schema at all — the mock *is* legacy web, and frames are addressed by name/URL pattern, never index. Only one driver exists today, so the seam is exercised rather than proven: agent, engine, and gate all speak Surface without importing Playwright; a second surface is Cuts item 2.

**Multi-tenant reuse:** artifacts identify the **vendor product** (`app: mockcore-teller`), not the tenant. Tenants bind via **overlays** (`src/schema/overlay.ts`): a required `baseUrl` binding plus patches that are additive and narrow by design — `prependStrategy` (tenant re-skinned a control), `addRecovery` (tenant-specific interstitial), `overrideWait` (slower instance). The schema gives overlays no way to change actions, params, outputs, or risk, so a tenant override can never silently change what a capability does. This is exercised live in both directions: the compiled artifact ships with only the handling its discovery run observed, and the `demo-fcu` overlay adds the session-timeout recovery — the evidence's timeout replay runs through it. And the re-skin case is proven against a second tenant instance ("Summit FCU", `npm run mock:summit`): the same discovered artifact fails honestly (`TARGET_NOT_FOUND` at the renamed control) without its overlay and succeeds with two `prependStrategy` patches — no re-recording; both runs are in the evidence. Drift management: strategy-rank regressions clustering by tenant mean that tenant's skin changed — patch the overlay or re-review; `cu replay --times N` aggregates that per-step strategy-rank distribution (plus status flapping and output consistency) into a stability report; the overlay's `^1` version range plus artifact semver keeps specialization safe.

## Escalation & handoff

**Detecting "stuck"** is explicit, not heuristic: an irreversible action under policy mode `escalate` pauses *before* acting, and an `escalate`-type recovery matches a state only a human can clear (supervisor authorization). With no operator attached, either case ends the run as `escalated / no_operator_available` — the system never guesses past a human decision. The same mechanism covers **discovery**: with `cu discover --hitl`, an irreversible click pauses the *recording* for approval on the live session (declined = never recorded, and the model is told not to retry; approved = the recorded action carries the intervention id, surfaced by the compiler as provenance) — risky flows are discoverable, not only replayable.

**Control transfer is mechanical.** The `SessionController` owns a control token; the ActionGate checks `holder()` on *every* action, so while a handoff is open the automation physically cannot act — possession is enforced at the same choke point as the allowlist. Nothing is "transferred" except control: the human operates the literal same browser context (same cookies, same server session), which is why state survives the handoff. The **intervention request** carries capability/step/intent, the reason, a live-state summary, a screenshot, and the legal resolution options; it is written to evidence and rendered to the operator.

**Handing back:** the operator resolves `approve` (the agent performs the pending risky action exactly once, with approval attached), `resume` (the human did the work), or `abort`. Resume verification reuses the engine's own machinery — after a handoff the engine re-enters its classification loop, so **the step's postcondition judges the human's work** with the same vocabulary that judges the machine's. Human actions during the handoff are captured (click/change/submit with a structural target description, values recorded as length only); the token check at the gate makes "no agent actions during a handoff" an invariant, not a log observation. The operator surface is a terminal prompt plus the live headed window (mocked thin, as the brief allows); a remote console would implement the same `Operator` interface over CDP screencast without touching the controller.

## Safety

The model: **one gate, allowlist-first, risk-tiered, redact-at-the-boundary.** The configurable policy allowlists origins, path prefixes (the mock's `/__faults` test harness is denied to the agent), and action kinds — checked against both the top-level page and the target element's own frame, since an allowed page can embed an off-origin frame. Risk classes: `read` and `reversible` proceed; `irreversible` is handled per policy — `block`, `confirm`, or `escalate` (the default, because in back-office banking the right reviewer for a one-off irreversible action is a person with context on the live session). Under the default policy, unattended replay of an irreversible flow is structurally impossible.

Data handling: sensitivity annotations drive redaction at the **write boundary** (one auditable place). Secrets never reach disk in artifacts, logs, transcripts, or results (`«secret:operatorPassword»`); `pii` values are masked in evidence while the caller receives real outputs on its channel. The discovery agent references secret params **by name** — the harness injects values, the model never sees them, and password field values are never observed at all. Sensitive extractions get the same treatment immediately on extraction: a `pii`-classed read is registered with the redactor immediately and shown to the model only in masked form, so it cannot echo the value into artifact prose — and the shipped artifact file itself passes through the redactor. The compiler additionally scrubs recorded neighbor text from artifact snapshots, keeping only anchor tokens. Known limits: screenshots are not redacted (a real deployment needs region masking driven by the same annotations); redaction is exact-string substitution over *classified* values — incidental on-screen data never declared as a param or output still appears in transcripts and screenshots, which a real deployment would address with app-profile field classification; and the allowlist constrains *where* the agent acts, not *what* it reads — extraction is at least auditable because `read` is a gated action.

## Cuts

Four earlier cuts have since been closed and are described above: the second tenant variant (the Summit re-skin, proven live), discovery-time HITL (`cu discover --hitl`), frame-scoped conditions with specificity-ranked checkpoint mining, and multi-run stability reporting (`--times N`).

Still deliberately out, each with a designed seam: **(1) Operator console UI** — terminal + live window only; next, a CDP-screencast web console implementing the same `Operator` interface. **(2) Desktop surface** — design only, per the brief; next, `surface/desktop/` behind the same `Surface` interface with the locator-strategy mapping above. **(3) Assisted LLM fallback on replay failure** — designed as one bounded, policy-checked step that *proposes an artifact patch* rather than silently healing, but not built, keeping the production path provably LLM-free. **(4) The approval workflow around stability** — the flakiness report exists; gating approval on it doesn't. **(5) Keystroke-perfect human capture and screenshot redaction** — event-level capture and text-only redaction shipped; limits documented above. **(6) Mid-flow resume, and finer-than-frame scoping** — `restartRun` is still the only session-recovery primitive (next: resume-from-step with a named re-auth subflow), and condition scoping stops at the frame: scoping to a region *within* a frame (a table, a panel) remains out. **(7) Re-recording the shipped artifacts against the improved compiler** — `readSavingsBalance` predates frame-scoped mining: several of its checkpoints (s3, s4, s9) and its success criteria assert text that also lives in the persistent chrome — the weakness that motivated the fix — and its final step s9 is a benign return-to-search click the model made *before* fencing its probe (the compiler pruned exactly what was fenced). `openSubAccount` predates discovery-time HITL. Both are kept deliberately: honest outputs of their recorded runs, with the improvements proven by tests; a fresh discovery run picks everything up.
